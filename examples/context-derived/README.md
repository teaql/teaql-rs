# Context-derived Fix, generated Q/E and SQLite

Run `python3 examples/context-derived/verify-local.py --output /new/evidence/path`
from the runtime repository. No published package or service is needed. The
verifier builds the **complete, unedited generated library**, checks its exact
file inventory/hashes and the six local crate identities, then runs twice against
one SQLite database without cleanup between rounds. Build outputs are removed
even on failure; logs, hashes, receipt and database remain for diagnosis.

The model is intentionally small: Catalog and Entry. The generated Clock and
`uniStr` defaults coexist with an application Checker/provider for prepared IP
and actor values. No HTTP work is done inside Check/Fix. All writes use generated
audited Save; Q reloads and E expressions check the real stored values. The SQL
executor/transaction and committed audit sink are independently counted.

Cases: create, changed Context with two clean saves, real business edit,
create-only field preservation, failed validation and restoration/retry, failed
Context provider and retry, indexed second-child failure, graph-wide Context
undo, changed child with clean parent/sibling, and physical SQLite readback.
Related mutations are explicitly composed with `include_pending_mutations_from`;
a loaded relationship does not imply a globally shared mutation ledger.

The fixture also loads persistent extensions through generated Q, updates only
an extension through audited Save, and checks Context defaults plus stored owner
version through E. Reassigning a known persisted extension value causes no
transaction, version bump or audit. Equal known NULL is distinct from an unknown
original. Restoring a field cancels only its own pending code, not other fields,
types, lifecycle or optimistic versions.

Readonly materialization is a separate case. Because the generated request has
no field-specific readonly-property selector, this controlled framework example
extends the generated Q builder's typed AST with an expression projection and
uses its generated `TeaqlRuntime` bridge with explicit request comment/purpose.
It uses no raw SQL. This is not a claim that a new generated selector exists.
The returned typed property survives a no-op audited Save under a changed Context.

The fixture is generated by `RustContextFixGenerationTest` in Model-Aware
Services with `-Dteaql.rust.context.fixture.output=<this directory>/fixture`.
Never edit fixture sources to make the test pass. Keep full-load validation and
the existing generated bounds checks; this example does not approve selective
validation or qualify published artifacts, every runtime example, or all
`FIX-14`–`FIX-19` scenarios.
