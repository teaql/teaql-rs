# 8.1.0: JSON and human runtime logging

Both `json` and `human` logging presentations are supported. JSON remains the
default. Select the presentation when composing the runtime logger; an explicit
application option takes precedence over the server `TEAQL_LOG_FORMAT` setting.
The exact accepted values are `json` and `human`.

Both presentations use the same privacy-safe event projection. Human SQL is
readable and indented across multiple lines. File output preserves severity,
UTF-8 whole-event rotation, UTC-day rollover, retention and concurrent writers.
A non-empty file using the other presentation is rejected before archive changes.
Plaintext SQL acknowledgement and existing privacy controls retain their meaning.

Choose a fresh destination when changing an existing file's presentation. Existing
generated APIs do not require regeneration for this logging feature.


Tracking: https://github.com/teaql/teaql-rs/issues/333; coordinated release https://github.com/teaql/teaql-conformance/issues/248.

Release status and the source, internal-artifact and public-delivery gates are
recorded separately in teaql/teaql-conformance,
`evidence/2026-11-18-logging-release`. These notes do not establish publication.

Ordinary audit files keep model-marked values masked when the separate plaintext debug acknowledgement is enabled. Explicit custom and debug sinks retain their existing opt-in behavior.
